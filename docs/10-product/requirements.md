# 要件定義書：レシピアプリ エンハンス（買い物リスト・AIサポート）

## 1. 概要
- 登録したレシピの画像やリンク先から、AIが材料を自動で読み取り、買い物リストとして一括コピーできるようにする
- チャットで今の気分や食べたいものを伝えると、登録済みレシピの中からAIがおすすめを提案する

## 2. 目的・背景
- レシピを見ながら買い物メモを手で書き写す手間をなくしたい
- レシピが増えてきて「今日は何を作ろう」と迷うことが多いので、気分に合うものを選ぶ手助けがほしい
- 提案のためには各レシピの「特徴」が必要になるため、材料の読み取りと同時に特徴もまとめて作成する

## 3. 対象ユーザー
- 自分と家族のみ（一般公開はしない）

## 4. 機能要件

### 進める順番
1. **フェーズ1：買い物リスト（材料の自動読み取り）＋特徴データの作成**
2. **フェーズ2：AIサポート（チャット提案）**

フェーズ2はフェーズ1で作る「特徴データ」を使うため、この順番で進める。

### 4-1. 材料の自動読み取り

| 項目 | 内容 |
|---|---|
| 動くタイミング | レシピを新規登録・編集して保存したあと、自動で開始 |
| 読み取り中の表示 | 「読み取り中…」と表示（数秒〜十数秒程度） |
| 読む順番 | **① URL（リンク先）を優先**して読み取る → **② URLがない・読めない場合は画像**から読み取る |
| 読み取り元：URL | レシピサイト・ブログは、リンク先のページから材料を読み取る |
| X のURL | 投稿の本文・画像・引用元の投稿・リンク先のレシピページを読む。動画の投稿は中身を読めないため画像へ |
| Instagram のURL | 投稿文（キャプション）を読む。投稿文に材料があれば読み取れる |
| 読み取り元：画像 | 登録された画像をAIが読み取る。材料が写ったスクショは高精度、完成写真のみの場合は推測 |
| 推測の目印 | 完成写真だけから推測した材料には「推測」の目印をつける |
| 読み取れなかった場合 | 「材料を読み取れませんでした」と表示し、手で入力できるようにする |
| 再読み取り | レシピ詳細に「もう一度読み取る」ボタンを置く |

### 4-2. 材料リスト（買い物リスト）

- レシピカードを開いた中に、そのレシピの材料リストを表示する（1レシピごと）
  - 材料リストは折りたたみにし、「材料・買い物リスト」ボタンを押したときだけ開く（ボタンには「買う物 4品」のように品数を出す）
- 各材料は、材料名と分量をまとめた**1行の文字**で持つ（例：`豚肉 150g`）。入力欄も1つにする
  - AIが読み取った材料は、画面に出さない「そろえた名前」（例：しょうゆ）も一緒に持ち、家にある物との照らし合わせに使う
  - 手で書き足した・書き換えた行は、分量らしい部分（大さじ・小さじ・数字・少々など）より前を材料名とみなして照らし合わせる（例：`塩麹大さじ1` → 塩麹。「塩」とは一致しない）
- 材料の追加・修正・削除ができる
- **「家にある物」リスト**
  - 「家にある物」リストに入っている材料は、最初からコピー対象外にする（材料リストには表示し、チェックを入れればコピー対象に含められる）
  - リストにない材料は、最初からコピー対象
  - 最初から入れておく品目：しょうゆ、みりん、酒、砂糖、塩、サラダ油、オリーブオイル、ごま油、こしょう、塩こしょう、酢、マヨネーズ、ケチャップ、味噌、めんつゆ、ポン酢、小麦粉、片栗粉、鶏がらスープの素、コンソメ、顆粒だし
  - リストはあとから追加・削除できる
    - 材料リストの各行から、ワンタップで「家にある物に追加」できる
    - 「家にある物」の一覧画面で、確認・削除・手入力での追加ができる
  - 照らし合わせ方：AIが材料名を一般的な名前にそろえ（例：「濃口醤油」→「しょうゆ」、「あらびき黒胡椒」→「こしょう」）、その名前がリストにあるかで判断する
  - リストを変更したら、登録済みのレシピにもすぐ反映する（読み取り直しは不要）
- **一括コピー**
  - ボタン1つで、コピー対象の材料をまとめてコピーする
  - 材料リストを開かなくても、「材料・買い物リスト」ボタンの横のコピーボタンからワンタップでコピーできる
  - 材料リストを開いたときは、下にもコピーボタンと「コピーされる内容を見る」を置く
  - 形式は1行1材料（例：`玉ねぎ 1個` 改行 `豚バラ肉 200g`）
  - スマホのメモ帳・リマインダーに貼り付けて使う想定（iPhoneのリマインダーは貼り付けると1行ずつ別の項目になる）
  - コピーしたら「コピーしました」と表示する

### 4-3. 特徴データの作成

- 材料の読み取りと同時に、AIがレシピの特徴を作成して保存する
- 特徴の例
  - 味の方向性（さっぱり／こってり／甘辛 など）
  - 主な食材
  - ジャンル（和・洋・中・エスニック など）
  - 手軽さ（簡単／ふつう／手間がかかる）
  - 季節感や向いている場面（夏向け、お弁当向き など）
- 特徴はAI相談で使うための裏のデータとして持つだけで、画面には表示しない（確認・修正の画面も作らない）

### 4-4. 既存レシピの一括読み取り

- この機能を公開するときに一度だけ、登録済みの全レシピについて材料と特徴をまとめて読み取る（読む順番は4-1と同じく URL優先 → 画像）
- 読み取れなかったレシピは一覧で確認できるようにする

### 4-5. AIサポート（チャット提案）

- チャット画面で「さっぱりしたもの」「鶏肉で簡単なの」などと話しかけると、AIがおすすめレシピを提案する
- 提案は**登録済みレシピの中からのみ**（新しい料理のアイデアは出さない）
- 提案されたレシピはタップするとレシピ詳細が開く
- 続けて「もっと軽めで」などと会話を重ねて絞り込める
- 会話履歴は保存しない（画面を閉じるとリセット）

### 4-6. 合言葉による保護

- AI機能（材料の読み取り・チャット）は、使うたびに料金が発生するため、簡単な合言葉で保護する
- 合言葉は一度入力すれば、その端末ではしばらく入力不要にする

## 5. 画面構成

### レシピ一覧（既存）
- 画面にチャットを開くボタンを追加する

### レシピ詳細（既存のカードを開いた中に追加）
- 材料リスト（材料名・分量・推測の目印・家にある物の目印・コピー対象のチェック）
- 各材料の「家にある物に追加」ボタン
- 「材料・買い物リスト」ボタン（押すと材料リストが開く）と、その横のコピーボタン
- 材料リストの下のコピーボタンと「コピーされる内容を見る」
- 材料の追加・編集・削除
- 「もう一度読み取る」ボタン

### レシピ登録・編集（既存）
- 保存後に自動で読み取りが始まる旨を表示

### AIチャット画面（新規）
- 入力欄と会話の表示
- 提案レシピはカード形式で表示し、タップで詳細を開く

### 家にある物の一覧（新規）
- 登録されている品目の一覧
- 削除、手入力での追加

### 合言葉入力（新規）
- AI機能を初めて使うときに表示

## 6. 非機能要件
- スマホでの利用を最優先（既存と同じくスマホ向けの画面づくり）
- 読み取りは数秒〜十数秒程度で完了すること
- 利用者は自分と家族のみ。一般公開はしない
- AIの外部サービス利用料は、個人利用で月数十〜数百円程度に収まる想定

## 7. 制約・注意事項
- **X・Instagram の読み取りは、公式に保証された方法ではない**（埋め込み表示やリンクプレビュー用の情報を使う）。SNS側の変更で急に読めなくなる可能性があり、その場合は画像からの読み取りか手入力になる
- Xの動画の投稿は中身を読めないため、材料を読み取るには材料が写ったスクショ画像の登録が必要
- **完成写真のみ**の場合、材料はAIの推測になるため精度が低い。候補を見て手で直す前提
- レシピサイトによっては、リンク先の読み取りを拒否される場合がある。その場合は画像からの読み取りか手入力になる
- AIの読み取り結果は必ず正しいとは限らない。修正できることを前提とする
- AIの外部サービスの利用登録と、合言葉の設定が事前に必要
